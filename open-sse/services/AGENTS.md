# open-sse/services

Grab-bag of engine-level services that sit below `src/sse/` (see `src/sse/AGENTS.md` for the
caller side — `handleChat`/`handleSingleModelChat`, `tierRouting`/`tokenLimitRouting`/
`modelCooldown` construction). This file documents the callee side: what `combo.js` actually
does with those inputs, plus the surrounding services (per-provider live model catalogs, OAuth
token refresh, usage fetchers, caches). Four rough clusters: **combo/fallback core**
(`combo.js`, `accountFallback.js`, `capacityAdapter.js`), **per-provider live model catalogs**
(`*Models.js`), **auth/token/identity** (`oauthCredentialManager.js`, `tokenRefresh.js`+
`tokenRefresh/`, `projectId.js`, `provider.js`), and **caching/model resolution**
(`model.js`, `responseCache.js`, `thoughtSignatureStore.js`, `modelsDevService.js`, `usage.js`+
`usage/`).

## Directory map

- `combo.js` (31KB) — the combo/fusion retry loop itself: `handleComboChat`, `handleFusionChat`, capability auto-switch, round-robin/sticky rotation. See below.
- `accountFallback.js` — `checkFallbackError` (config-driven `ERROR_RULES` from `config/errorConfig.js`) + exponential backoff (`getQuotaCooldown`) + model-lock helpers (`modelLock_${model}` field builders) consumed by both `combo.js` (per-model) and `src/sse/services/auth.js` (per-account).
- `capacityAdapter.js` — global fallback model pools per input-modality capability (vision/pdf/audioInput/videoInput), consumed by `src/sse/handlers/chat.js` before `combo.js` even runs; also `stripHistoryForContext`/`withCapacityAdapterStripping` to fit a smaller adapter model's context window.
- `compact.js` — **dead code**: an old, simpler `getComboModelsFromData`/`handleComboChat` pair (no rotation, no tier/token-limit/cooldown routing, 5xx-only fallback). Zero importers repo-wide. See Pitfalls.
- `model.js` — `parseModel`/`resolveProviderAlias`/`getModelInfoCore`/`inferProviderFromModelName`: the core "alias/model string → {provider, model}" parser. `src/sse/services/model.js` wraps this with localDb combos/aliases — don't confuse the two.
- `provider.js` — request-format detection (`detectFormat`: openai/claude/gemini/openai-responses/antigravity) + provider config lookup (`getProviderConfig`, openai-compatible / anthropic-compatible prefix handling, `resolveTransport` for multi-endpoint providers). Owns "what shape is this request / what does this provider need", not model-string parsing (that's `model.js`).
- `oauthCredentialManager.js` — provider-agnostic credential lifecycle glue: `shouldRefreshCredentials` (expiry lead time + codex's `maxRefreshAgeMs` staleness check), `mergeRefreshedCredentials` (normalizes whatever a provider's refresh handler returned into a DB-shaped patch), `withCredentialRefreshLock`/`refreshProviderCredentials` (in-memory dedup so concurrent requests on the same credential share one refresh).
- `projectId.js` — Google Cloud Code `loadCodeAssist`/`onboardUser` project-ID resolution for gemini-cli/antigravity, with a 1h in-memory cache + pending-fetch dedup + a 10-min background sweep (`startCacheCleanup`, auto-started on import).
- `tokenRefresh.js` — re-exports all provider refresh functions from `tokenRefresh/providers.js`, plus `REFRESH_HANDLERS` (provider → refresh fn dispatch table), `getAccessToken`/`refreshTokenByProvider`, Vertex service-account JWT minting (`refreshVertexToken`), `formatProviderCredentials`.
- `tokenRefresh/providers.js` — the actual per-provider OAuth refresh implementations (~700 lines: xai, claude, google, codex, kiro [3 auth methods], iflow, github, copilot, codebuddy-cn/intl, trae, cline, zed [no-op], windsurf [no-op]). Most delegate to a generic `refreshAccessToken` via a `REFRESH_PROFILES` table; a few (kiro, trae, codebuddy) have bespoke bodies.
- `tokenRefresh/dedup.js` — `dedupRefresh(provider, oldToken, fn)`: in-flight promise cache + 10s post-completion result cache, keyed by `${provider}:${oldToken}`, so concurrent requests refreshing the same token don't fire duplicate upstream calls.
- `clinepassModels.js`, `copilotModels.js`, `cursorModels.js`, `grokCliModels.js`, `kimchiModels.js`, `kiroModels.js`, `qoderModels.js` — per-provider **live** model catalog fetchers (account-specific, supplementing/replacing the static registry). See "Model catalog fetchers" below for the shared shape and inconsistencies.
- `modelsDevService.js` — unrelated to the above catalogs: syncs pricing/context-window data from the external `models.dev` catalog into local DB (`modelsDevPricingRepo`), for dashboard cost display. Own alias table (`OAUTH_ALIASES`), own ETag-based fetch cache.
- `responseCache.js` — small in-memory LRU (`ResponseCache`, default 100 entries / 5 min TTL) keyed by `hash(model, messages, temperature, max_tokens, top_p)`; singleton via `getResponseCache()`. Opt-in, wired from `chatCore.js`/settings — not on the hot path unless enabled.
- `thoughtSignatureStore.js` — RAM (1h TTL, capped 2000) + SQLite-backed (7d TTL, capped 10000, via `src/lib/db/helpers/kvStore.js`) cache of Gemini "thought signatures" keyed by `tool_call_id` (+ optional `sessionId` namespace) — Gemini requires echoing these back on subsequent turns that reference a prior tool call's thinking, so translators persist them here across the request/response boundary.
- `usage.js` — provider → quota/usage-fetch dispatch table (`USAGE_HANDLERS`), spreads `EXTRA_USAGE_HANDLERS` from `@9router/providers/usage/index.js` (see root `AGENTS.md`'s "other provider-keyed maps" table). Delegates to `usage/*.js`.
- `usage/*.js` — one file per provider's quota-fetch implementation (`github.js`, `google.js`, `claude.js`, `codex.js`, `kiro.js`, `minimax.js`, `codebuddy-cn.js`, `grok-cli.js`, `kimi.js`, `deepseek.js`, `opencode-go.js`, `groq.js`, `zed.js`, `xiaomi-mimo.js`, `glm.js`, `misc.js` [iflow/ollama/vercel-ai-gateway/qoder], `grokCliQuotaFrame.js` [binary frame decoder for grok-cli]) + `shared.js` (common helpers: `parseResetTime`, `toFiniteNumber`, `fetchWithTimeout`, `U(id)` registry lookup).

## Combo/fusion internals (`combo.js`)

`handleComboChat({ body, models, handleSingleModel, log, comboName, comboStrategy, comboStickyLimit, tierRouting, tokenLimitRouting, modelCooldown, onModelError })` (`combo.js:296`) builds the try-order once, then loops:

1. **Rotation** — `getRotatedModels` (`combo.js:211`) only acts when `comboStrategy === "round-robin"`. State is a module-level `Map` (`comboRotationState`, `combo.js:91`) keyed by `comboName`, tracking `{ index, consecutiveUseCount }`. `comboStickyLimit` requests are served from the same starting model before the index advances — i.e. this is sticky-round-robin, not per-request rotation. In-memory only: a restart resets everyone to model 0.
2. **Token-limit bypass** (`combo.js:305`) — hard-drops models whose configured max-input can't fit the prompt (`filterModelsByTokenLimit`, `@9router/token-limit-routing`). Runs first because a model that can't fit is a near-certain failure, so later reorders should only see viable candidates. Fail-open: never empties the list.
3. **Cooldown filter** (`combo.js:318`) — drops models that failed inside *this same combo* within the TTL (default 5 min, `@9router/model-combo-cooldown`, `packages/model-combo-cooldown/config/defaults.js`). Scope is `(comboName, modelStr)` — lazy-expired on read, no background timer. Fail-open: if every model is cooling down, the filter is a no-op (`filterSkippedComboModels`).
4. **Tier/cost reorder** (`combo.js:330`) — `reorderByCost`/`reorderFreeTierFirst`/`classifyTask` from `@9router/tier-routing`. Runs *before* the capability auto-switch so hard capability requirements always win; cost only breaks ties within a capability tier. `tierRouting.overBudget` forces free-tier-first regardless of mode; `"task-aware"` mode leaves "critical" (agentic/code) tasks in their original order and only reorders non-critical ones.
5. **Capability auto-switch** (`combo.js:351`, `reorderByCapabilities` at `combo.js:66`) — `detectRequiredCapabilities` (`combo.js:108`) scans the request for vision/pdf/audioInput/videoInput, scoped to the **trailing user turn only** (`trailingUserItems`, `combo.js:97`) so older multimodal history doesn't pin the whole combo to a vision model. Stable 3-tier sort (satisfies hard+soft / hard-only / neither); never drops a model.
6. **The try loop** (`combo.js:366`) — for each model in the final order: call `handleSingleModel(body, modelStr)`. On `result.ok` → return immediately. On failure, parse the error body, call `checkFallbackError` (`accountFallback.js`) — if `shouldFallback` is false, return that error response as-is (no further fallback); otherwise mark cooldown (`markComboModelFailed`) and continue. **Special case**: a transient 502/503/504 with `cooldownMs <= 5000` makes the loop `await` that cooldown in-place before moving to the next model, so a briefly-overloaded provider gets one real chance rather than being skipped instantly. Thrown exceptions are caught and treated the same as a failed response. After all models are exhausted, returns 503 (deliberately not 406 — the request wasn't invalid, providers were just unavailable) with the earliest `retryAfter` seen across all attempts. `onModelError?.({ comboName, modelStr, status })` fires on every fallback/exception branch, **independent of `modelCooldown?.enabled`** — it's the error-stats logging hook (`plans/2026-09-22-provider-model-error-stats-planning.md`), wired by `src/sse/handlers/chat.js` to `src/lib/errorLogDb/errorLogRepo.js`'s `logModelError` (never called directly from `combo.js`, since `open-sse/` must not import `src/`).

`handleFusionChat({ body, models, handleSingleModel, log, comboName, judgeModel, tuning })` (`combo.js:615`) is a different shape — parallel fan-out + judge synthesis, not sequential fallback:

1. 0 or 1 panel model → degenerate cases (400 error, or answer directly).
2. Panel calls are forced `stream: false` with `tools`/`tool_choice`/`stream_options` stripped, and tool turns flattened to prose (`flattenToolHistory`, `combo.js:24`) — panel models must produce complete prose for the judge, and dropping `stream_options` avoids some providers (DeepSeek) rejecting it without `stream: true` (issue #3024, `combo.js:636`).
3. `collectPanel` (`combo.js:563`) is quorum-grace collection: once `minPanel` (default 2, floor 2) calls succeed, start a short grace timer (`stragglerGraceMs`, default 8s) for the rest, then proceed with whatever arrived — bounded by `panelHardTimeoutMs` (default 90s). This caps the wall-clock penalty from the single slowest panel model.
4. Degrades gracefully: 0 successful answers → 503; exactly 1 → return it directly (no judge call, no fusion).
5. The judge (`judgeModel` or `panel[0]`) gets a synthesized prompt (`buildJudgePrompt`, `combo.js:519`) with panel answers anonymized as "Source N" (so the judge weighs content, not brand reputation), analyzes consensus/contradictions/blind-spots, then writes one answer — appended as a new user turn (`appendUserTurn`) preserving the original conversation. The judge call keeps the *client's* original stream/tools, so streaming still works end-to-end for fusion combos.
6. **`modelCooldown`/`tierRouting`/`tokenLimitRouting` are not applied to `handleFusionChat` at all** — those three params only exist on `handleComboChat`'s signature (confirmed also by `src/sse/AGENTS.md`).

## Model catalog fetchers (`*Models.js`)

Shared shape across `copilotModels.js`, `cursorModels.js`, `kiroModels.js`, `qoderModels.js`, `kimchiModels.js`, `grokCliModels.js`, `clinepassModels.js`: `resolve<Provider>Models(credentials, options)` → live-fetch the account's actual model list (because the static registry lags behind what an account is entitled to), cache per-credential (TTL 5min–1h depending on provider), 401/403 triggers one token-refresh-and-retry. Each hits a different upstream shape: Copilot is a REST JSON list, Cursor is HTTP/2-only protobuf (`agent.v1.GetUsableModelsResponse`, hand-rolled varint decoding in `utils/cursorProtobuf.js`), Kiro expands one upstream model into up to 4 synthetic `-thinking`/`-agentic` variants, Qoder additionally exchanges a PAT (`pt-...`) for a short-lived job token (`jt-...`) and caches per-model `model_config` blocks (chat silently downgrades models if the wrong config is sent).

## Pitfalls

| Issue | Where |
|---|---|
| `compact.js` is dead code — an older, simpler duplicate of `combo.js`'s `getComboModelsFromData`/`handleComboChat` (no rotation, no tier/token-limit/cooldown routing, treats any `status < 500` as terminal). Zero importers repo-wide (`grep services/compact` finds nothing). Don't extend it by mistake instead of `combo.js`. | `open-sse/services/compact.js` |
| `handleFusionChat` ignores `tierRouting`/`tokenLimitRouting`/`modelCooldown` entirely — only `handleComboChat` consumes them. A fusion combo with an oversized-prompt panel model or a model that's over budget will still be called every time. | `combo.js:615` (signature has no such params) |
| Catalog fetcher return contracts are inconsistent: most `resolve*Models` return `null` on failure so callers fall back to the static registry, but `resolveGrokCliModels` returns `{ models: [], warning: "..." }` instead — a caller written against the `null` contract (falsy check) still works, but one checking `result === null` specifically will misclassify a Grok CLI failure as "empty but successful". | `grokCliModels.js:81,114,123,125` vs. the `null`-returning pattern in `copilotModels.js`/`cursorModels.js`/`kiroModels.js`/`kimchiModels.js`/`qoderModels.js` |
| `getRotatedModels`'s round-robin state (`comboRotationState`) and the model-combo-cooldown store are both process-local `Map`s — in a multi-instance deployment each instance rotates/cools down independently; not shared via DB or Redis. | `combo.js:91`, `packages/model-combo-cooldown/cooldownStore.js:13` |
| The transient-error in-loop wait (`await new Promise(r => setTimeout(r, cooldownMs))`) blocks the whole combo request for up to 5s per transient failure — with several transient models in a row this adds up on the critical path of a single user request (no cap on how many models can trigger this in one request). | `combo.js:411-415` |
| `reorderByCapabilities`/`detectRequiredCapabilities` only scope modality detection to the trailing user turn, but `stripHistoryForContext` (`capacityAdapter.js`) separately caps history at a *char-count* estimate (`CHARS_PER_TOKEN = 4`), not a real tokenizer — on token-dense content (code, non-English text) this can under- or over-trim relative to the adapter model's real context window. | `capacityAdapter.js:102-156` |
| `modelsDevService.js`'s `OAUTH_ALIASES` and `src/sse/services/model.js`'s `CORE_ALIASES`/provider registry aliasing are two independently maintained alias tables for largely the same provider set — adding a new OAuth provider alias in one place doesn't propagate to the other. | `modelsDevService.js:16-31` vs `provider.js`-adjacent alias tables in `src/sse/services/model.js` |
| `inferProviderFromModelName` (`model.js:159`) swallows a missing `@9router/services/model.js` package via bare try/catch and silently falls back to `"openai"` — a typo'd package path or a moved extra-prefix module fails invisibly (same pattern flagged in `src/sse/AGENTS.md` for the wrapper). | `model.js:169-176` |
